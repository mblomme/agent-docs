# Section guide

Start with Name and Purpose; complete the remaining sections as information becomes available.

| Section | What to document |
| --- | --- |
| Name | The team's agreed context name. |
| Purpose | Business responsibilities, value, and beneficiaries; omit implementation details. |
| Strategic Classification | Domain Type: core, supporting, or generic. Business Model Role: revenue generator, engagement creator, or compliance enforcer. Evolution: genesis, custom built, product, or commodity. |
| Domain Roles | Behavioral roles, such as analysis or workflow execution; consider whether responsibilities belong together. |
| Inbound Communication | Interactions initiated externally: collaborator, command/query/event, and relationship type. Collaborators may include contexts, frontends, or direct users. |
| Outbound Communication | Interactions initiated by this context; use the same details as inbound. Messages imply neither asynchronous delivery nor a message bus. |
| Ubiquitous Language | Context-specific business terms and meanings. |
| Business Decisions | Business rules and policies. |
| Assumptions | Unconfirmed premises behind design choices. |
| Open Questions | Unresolved questions and uncertainties. |
